upstream commit: c854090f55e39909f167b01ba86b0ec89fc87e82
copied:          2026-11-14
local divergence: none

This copy is byte identical to that upstream commit. The launch hand-off and
`--no-launch` that used to be a local divergence here (#72) now live upstream,
together with the `--client` choice the download page passes, so there is
nothing to re-apply by hand any more.

Why a copy exists at all: the site serves https://opencrabs.com/install.sh, and
nginx ships whatever sits in src/root-files. Nothing regenerates it at build
time, so it can drift from the repo installer. It did: the release started
shipping OpenCrabs.app and this copy kept demanding a loose `opencrabs` file, so
every macOS install failed at the layout check (#62). It drifted again in the
other direction afterwards: the site copy knew `--no-launch` and nothing about
`--client`, so the download page asked which client the reader wanted and then
handed the flag to a script that rejected it (#2931).

To re-vendor after changing the upstream installer:

    cp ~/srv/rs/opencrabs/src/scripts/install.sh src/root-files/install.sh
    chmod 755 src/root-files/install.sh
    # update the commit and date above
    cmp src/root-files/install.sh ~/srv/rs/opencrabs/src/scripts/install.sh

Keep the copy byte-identical. Any local edit here is invisible to the repo's
own tests and to anyone reading the upstream file, and the next re-vendor
silently reverts it. Change the upstream file instead, then copy it down. That
is how the two copies diverged twice.

.github/workflows/test-install-sh.yml installs the latest release for real on
macOS and Linux whenever this file changes and once a week. That is the guard
that a release layout change cannot orphan this copy again: a parse test would
have passed while every Mac install failed.
