OpenCrabs

CLI Commands

У OpenCrabs полноценный CLI с 20+ субкомандами для управления каждым аспектом агента.

Использование

opencrabs [COMMAND] [OPTIONS]

/cost-estimateОценка стоимости: оценка стоимости разработки кодовой базы, разбивка ROI с учётом ИИ и справедливая рыночная оценка. Спрашивает бизнес-контекст, прежде чем дать диапазон оценки.

Предложение обновления при старте

Когда доступна новая версия, по центру экрана заставки появляется диалог с предложением принять (Enter) или пропустить (Esc). Принятие автоматически запускает /evolve. После обновления бинарник перезапускается, и заставка показывает новую версию.

Команды channels

/doctor, /help, /usage, /evolve, /restart, /exit и системные команды работают напрямую в Telegram, Discord, Slack и WhatsApp, минуя LLM. Они исполняются мгновенно и возвращают результат в channel.

/restart и /exit объявляют о себе перед действием: когда процесс уже убит, докладывать об ошибке некому. Обе команды только для owner, как и любая другая, меняющая работающий процесс. /exit: единственная команда, из которой нет пути назад через чат: для восстановления нужен доступ к машине, где работает OpenCrabs.

С v0.3.80 остановка своими словами тоже работает: просьба остановиться естественным языком действует в channels и в TUI, а не только голое слово «stop».

Вся логика команд channels централизована в src/channels/commands.rs (847 строк): общий обработчик, убирающий дублирование логики команд между 5 реализациями channels. Каждый channel делегирует к try_execute_text_command() для единообразного поведения.

/evolve в channels теперь выполняется напрямую (скачивает и устанавливает бинарник), без обращения к LLM. Раньше шло через агента.

Режим чата

# Default: launch TUI
opencrabs

# Same as above
opencrabs chat

Режим агента

Неинтерактивный режим для скриптов и автоматизации:

# Interactive multi-turn chat
opencrabs agent

# Single-message mode
opencrabs agent -m "Какие файлы менялись сегодня?"

Режим демона против TUI

OpenCrabs работает в одном из двух режимов. Выберите подходящий машине. Для одного профиля запускайте только что-то одно.

РежимКак запускатьЧто этоГде использовать
TUI (интерактивный)opencrabsПолный терминальный интерфейс: панели чата, sessions, настройки. Ваши channels тоже работают и делят вашу session.Машина, за которой вы сидите (ноутбук/десктоп)
Демон (headless)opencrabs daemon, or install as a service: opencrabs service install && opencrabs service startБез интерфейса. Только channels (Telegram, Discord, Slack, WhatsApp) + cron. Переживает перезагрузки, обрывы SSH и падения.Всегда включённая машина или VPS

Почему не оба сразу?

Кред бота (например, токен Telegram) может держать только один живой опрос getUpdates. Если демон и TUI одновременно владеют токеном одного профиля, он�� дерутся (HTTP 409), и channel отваливается.

TUI всегда побеждает

Когда вы открываете TUI, пока для того же профиля работает демон, TUI сначала выключает демона, забирает channels и показывает об этом баннер. Ваши channels уже настроены, поэтому они просто возобновляются без переподключения. Демон остаётся выключенным, пока вы не запустите его снова (opencrabs service start или повторный opencrabs daemon).

На машине, где обычно работает демон, повседневный поток такой: открывайте opencrabs, когда хотите поработать с агентом; закрывайте TUI и делайте opencrabs service start, когда снова нужен headless-режим.

Автозапуск при загрузке

  • Демон: используйте установщик сервиса (opencrabs service install); он настраивает systemd (Linux) / launchd (macOS) на старт при загрузке и перезапуск при падении. Это рекомендуемая схема для постоянной работы.
  • TUI: чтобы терминальный интерфейс открывался автоматически при входе, используйте автозапуск терминала/десктопа, а не установщик сервиса:
    • Linux-десктоп: положите файл .desktop в ~/.config/autostart/ с Exec=x-terminal-emulator -e opencrabs.
    • macOS: Системные настройки > Основные > Объекты входа > добавьте скрипт .command, запускающий opencrabs.
    • VPS по SSH: запускайте внутри tmux/screen и переподключайтесь. На headless-VPS вам обычно нужен демон, а не TUI.

Настоятельно рекомендуется ежедневным пользователям. Если планируете пользоваться OpenCrabs каждый день, попросите его настроить себя как системный сервис. Просто скажите что-то вроде «настрой себя запускаться вместе с компьютером» или «убери автозапуск сервиса». Агент сам настроит и уберёт launchd (macOS) или systemd (Linux) автоматически.

Держим TUI работающим на VPS (tmux)

Если вам нужен полноценный интерактивный TUI всегда под рукой на удалённом сервере (а не headless-демон), tmux - ваш путь. Ваша session переживает обрывы SSH, сон ноутбука и капризные соединения.

1. Установите tmux

# Debian / Ubuntu
sudo apt install tmux

# RHEL / CentOS / Fedora
sudo yum install tmux

2. Найдите, куда установлен opencrabs

which opencrabs

# If that returns nothing, search the whole filesystem
find / -name "opencrabs" -type f 2>/dev/null

3. Запустите именованную сессию tmux

tmux new -s opencrabs

4. Запустите opencrabs внутри неё

opencrabs

5. Отключитесь (opencrabs продолжит работать)

Нажмите Ctrl+B, затем D. Теперь можно закрыть SSH - opencrabs продолжит работать.

6. Подключитесь позже

tmux attach -t opencrabs

Вот и всё. Возвращайтесь с любой машины, подключайтесь и продолжайте с места, где остановились. Если вам нужны только channels (Telegram, Discord, Slack, WhatsApp) в headless-режиме без TUI, демон подойдёт лучше: opencrabs service install && opencrabs service start.

Эндпоинт здоровья

Добавьте в config.toml, чтобы открыть проверку здоровья:

[daemon]
health_port = 8080

Затем GET http://localhost:8080/health возвращает 200 OK с JSON-статусом. Полезно для сторожа systemd, мониторов аптайма или балансировщиков.

Управление сервисом

Установите OpenCrabs как системный сервис (launchd на macOS, systemd на Linux):

opencrabs service install
opencrabs service start
opencrabs service stop
opencrabs service restart
opencrabs service status
opencrabs service uninstall

Сервисы с учётом профилей

Каждый профиль получает собственный независимый сервис:

# Install a specific profile as a service
opencrabs -p hermes service install
opencrabs -p hermes service start

# Each profile gets its own service name
# macOS: com.opencrabs.daemon.hermes
# Linux: opencrabs-hermes.service

# Manage independently
opencrabs -p hermes service status
opencrabs -p hermes service stop
opencrabs -p hermes service uninstall

Несколько профилей могут работать одновременно как демоны-сервисы с полной изоляцией.

Переменная окружения OPENCRABS_PROFILE

Поставьте OPENCRABS_PROFILE=hermes, чтобы выбирать профиль без флага -p. Полезно для сервисов systemd, задач cron и режима демона.

Траблшутинг: демон не поднимается

Если opencrabs service status говорит stopped:

  1. Вы открывали TUI? Запуск opencrabs намеренно выключает демона, чтобы интерактивная session завладела channels. Демон остаётся выключенным, пока вы снова не выполните opencrabs service start.
  2. Старые сборки могут ещё иметь Restart=on-failure вместо Restart=always. Перегенерируйте юнит через opencrabs service install (затем service start), чтобы получить политику вечного перезапуска.
  3. Конфигурация, ключи, команды и инструменты перезагружаются на лету. Правка config.toml или keys.toml никогда не требует перезапуска демона. Если изменение не применяется, поищите в логах строку ConfigWatcher: reloaded вместо перезапуска.

Управление cron

# List all cron jobs
opencrabs cron list

# Add a new cron job
opencrabs cron add \
  --name "Daily Report" \
  --cron "0 9 * * *" \
  --tz "America/New_York" \
  --prompt "Check emails and summarize" \
  --provider anthropic \
  --model claude-sonnet-4-20250514 \
  --thinking off \
  --deliver-to telegram:123456

# Remove a cron job (accepts name or ID)
opencrabs cron remove "Daily Report"

# Enable/disable (accepts name or ID)
opencrabs cron enable "Daily Report"
opencrabs cron disable "Daily Report"
