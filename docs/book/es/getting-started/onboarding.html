OpenCrabs

Onboarding

A first run does not open the wizard. OpenCrabs goes straight to the chat, with its built-in provider already provisioned and the agent greeting you. The onboarding wizard is opt-in: run opencrabs --onboard, or /onboard from inside a session.

Los vídeos guiados están en la página Vídeos de onboarding.

Primer arranque: aterrizas en el chat

No hay ningún asistente en una instalación nueva. OpenCrabs abre el chat, pone en marcha el proveedor integrado y te saluda:

  1. config.toml y keys.toml se escriben desde el ejemplo incluido si todavía no están.
  2. [providers.opencrabs] se activa. El ejemplo lo trae desactivado, así que esto es lo que lo convierte en el proveedor activo.
  3. La instalación pide a inference.opencrabs.com su propio token y lo guarda en keys.toml. El token se reutiliza en cada arranque posterior, así que esto pasa una vez.
  4. El agente lee sus brain files y te saluda con el modelo que está ejecutando.

Si la petición del token falla (sin conexión, proxy inalcanzable), sigues aterrizando en un chat que funciona con una línea diciendo qué pasó. Escribe /onboard para elegir otro proveedor, o arregla la conexión y reinicia. El onboarding solo se marca completo cuando el proveedor integrado llegó a arrancar de verdad, así que el siguiente arranque lo reintenta en vez de dejarte en un chat sin proveedor.

Lo que tienes sin configurar nada

CapacidadModelNotes
Chatdeepseek-v4.1-flash200k de contexto, fijo

Generación de imágenesgemini-2.5-flash-imageSe sirve solo en la ruta de imágenes, nunca como modelo de chat

Gratis, sin cuenta, sin clave que pegar, sin límites de uso durante la fase experimental. El proxy limita el abuso (ráfagas de peticiones, creación masiva de instalaciones) y el uso normal no lo toca. Las peticiones van a inference.opencrabs.com, que las reenvía al host del modelo upstream. Todo el detalle, incluido dónde vive el token y cómo salir: OpenCrabs (integrado).

Para pasar a otro proveedor más adelante, escribe /models y elige uno, o ejecuta /onboard y elige Advanced.

Flujo de onboarding

El asistente es una TUI controlada con el teclado y tiene 8 pasos. Navega con las flechas, usa Tab para avanzar y Esc para volver.

PasoPantallaQué haces
1Selección de modoElige QuickStart (omite los channels) o Advanced
2WorkspaceElige un directorio de trabajo para las operaciones con archivos
3Proveedor y autenticaciónSelecciona el proveedor → pega la clave de API → elige el modelo (se obtiene en vivo)
4ChannelsSpace para activar o desactivar cada channel → Enter en cada uno para configurarlo
5VozProveedor de STT (Groq, Whisper local o desactivado) + voz de TTS
6ImagenActivación de Vision + modelo de generación + clave de API
7DaemonInstala el daemon en segundo plano (opcional)
8Brain SetupGenera SOUL.md automáticamente a partir de tu perfil

Configuración de channels (paso 4)

La pantalla de channels muestra 5 integraciones: Telegram, Discord, WhatsApp, Slack y Trello.

  • Space activa o desactiva un channel
  • Enter en un channel activado abre su pantalla de configuración (token, IDs, listas de permitidos)
  • Enter en Continue o Tab pasa al siguiente paso
  • Cada pantalla de configuración de channels tiene un botón Test Connection

Consulta Channels Overview para ver la guía de navegación completa.

Al terminar el onboarding, tu agente se inicia y se presenta. Lee sus archivos de brain (SOUL.md, AGENTS.md, TOOLS.md) y empieza una conversación.

Bootstrap

En la primera ejecución, el agente pasa por una fase de bootstrap:

  • Te conoce (nombre, preferencias, forma de trabajar)
  • Define su identidad (nombre, personalidad, emoji)
  • Abre SOUL.md contigo para hablar de sus valores
  • Configura USER.md con tu perfil

El archivo de bootstrap (BOOTSTRAP.md) se elimina solo al completarse.

Migrar desde otra herramienta

¿Ya usas ClaudeCode, OpenClaw, Hermes u otro arnés de agente de IA? Tu agente puede migrar tus datos existentes (memoria, skills, comandos personalizados, preferencias) a sus propios archivos de brain usando lenguaje natural. No necesitas mover archivos a mano.

Funciona con cualquier agente o arnés de programación que guarde su configuración en local. La migración busca en tu sistema de archivos los directorios de configuración de la otra herramienta, lee su contenido y lo convierte al formato de archivos de brain de OpenCrabs (SOUL.md, USER.md, TOOLS.md, MEMORY.md, AGENTS.md, CODE.md).

Migración guiada

Si quieres revisar qué se migra antes de que ocurra:

Busca en local mis datos de ClaudeCode/OpenClaw/Hermes (o de cualquier otro arnés de agente que haya usado) y audita una migración a nuestros propios archivos de brain. Informa cuando termine y ejecútala cuando yo confirme y apruebe.

El agente:

  1. Busca en tu sistema de archivos los directorios de configuración de la otra herramienta
  2. Lee y analiza todos los archivos relevantes (memoria, comandos, skills, preferencias)
  3. Genera una auditoría que muestra exactamente qué se asigna a dónde
  4. Espera tu confirmación
  5. Ejecuta la migración e informa de un desglose completo

Migración autónoma

Si solo quieres que se haga:

Busca en local mis datos existentes de agentes o arneses y migra todo a nuestros propios archivos de brain, sin necesidad de mi aprobación. Adelante: planifica y ejecuta, e informa cuando termine con un desglose completo.

El agente omite el paso de auditoría, planifica la migración internamente, la ejecuta y te entrega un resumen de todo lo que se movió.

Qué se asigna

FuenteDestinoEjemplo
Memoria / CLAUDE.md / archivos de contextoMEMORY.mdDecisiones del proyecto, contexto previo
Comandos personalizadoscommands.tomlComandos slash y sus definiciones

Consejo: Ejecuta la migración justo después del onboarding, mientras el contexto está fresco. El agente ya tiene tu USER.md y tu SOUL.md del asistente, así que puede combinarlos de forma inteligente en lugar de sobrescribirlos.

Directorio de trabajo

El agente opera dentro de un directorio de trabajo para las operaciones con archivos. Cámbialo con:

  • Comando /cd en el chat
  • Selector de directorios en la TUI (Tab para seleccionar)
  • Herramienta config_manager set_working_directory

El directorio de trabajo se guarda por session. Al cambiar de session, el directorio se restaura automáticamente.

Pista de filtro de modelos (v0.3.78)

El selector de modelos del onboarding ahora siempre muestra una pista de filtro encima de la lista de modelos (“Type to filter…”). Antes, la pista solo aparecía después de empezar a escribir, así que los usuarios no sabían que había filtrado. Además, un ID de modelo escrito exactamente ahora tiene prioridad sobre una coincidencia parcial: si escribes claude-opus-4-8 exactamente, selecciona ese modelo aunque otros modelos contengan la misma subcadena.
